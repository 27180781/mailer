# אפליקציית Zapier

אפליקציה שמחברת את מערכת הדיוור ל-Zapier. ההתחברות במפתח API, וה-triggers מיידיים: כש-Zap מופעל, Zapier רושם webhook במערכת, וכשהוא כבוי ה-webhook נמחק.

## מה יש בה

**Triggers (מיידיים):**

| שם | מתי |
| --- | --- |
| מנוי חדש | איש קשר חדש (API, טופס הרשמה, אפליקציה). ייבוא קובץ לא מפעיל |
| מנוי נוסף לרשימה | אפשר לבחור רשימה מסוימת. בהרשמה כפולה, רק אחרי האישור |
| מנוי הסיר את עצמו | בקישור ההסרה במייל או דרך ה-API |
| פרטי מנוי עודכנו | |
| אירוע במייל | נמסר, נפתח, לחיצה, חזר, ספאם, נכשל, הסרה |

**Actions:** הוספה או עדכון של מנוי (כולל רשימות ושדות נוספים), עדכון פרטי מנוי, הסרת מנוי מהדיוור, החזרת מנוי שהוסר, צירוף לרשימה, הוצאה מרשימה, מחיקת מנוי, יצירת רשימה, שליחת מייל.

**Search:** חיפוש מנוי לפי מייל, ו"חיפוש או יצירה".

## פרסום (פעם אחת)

צריך חשבון ב-Zapier ו-Node.js 18 ומעלה.

```bash
npm install -g zapier-platform-cli
```

```bash
cd integrations/zapier && npm install
```

```bash
zapier login
```

```bash
zapier register "Retzef Mailer"
```

```bash
zapier push
```

`register` יוצר את הקובץ `.zapierapprc` עם מזהה האפליקציה. כדאי לשמור אותו במאגר, כדי ש-`push` הבא יעדכן את אותה אפליקציה.

אחרי `push` האפליקציה פרטית: מופיעה רק בחשבון שלכם. כדי לתת ללקוחות, ב-https://developer.zapier.com פותחים את האפליקציה → **Sharing** ומעתיקים את קישור ההזמנה. כדי שתופיע לכולם בחיפוש של Zapier, מגישים אותה לבדיקה (Publishing). Zapier דורשים לוגו, תיאור ובדרך כלל כמה משתמשים פעילים.

## עדכון

משנים את `version` ב-`package.json` ומריצים `zapier push`. כדי להעביר משתמשים קיימים לגרסה החדשה: `zapier promote <version>`, ואחר כך `zapier migrate <old> <new>`.

## בדיקה

הבדיקה רצה מול שרת אמיתי. כדאי מפתח בדיקה (`mk_test_`), שלא שולח מיילים באמת:

```bash
BASE_URL=https://mail.retsef.co.il MAILER_API_KEY=mk_test_... npm test
```

כתובת המערכת מוגדרת ב-`common.js`. אם המערכת עוברת כתובת, משנים שם ומריצים `zapier push`.
